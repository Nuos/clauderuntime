0. 总体反馈

这轮针对 B4 遗留问题的优化是有效且方向正确的第一批修复。本轮最有价值的变化，不是测试数量增加，而是项目开始主动纠正 B4 阶段过早的 VERIFIED 结论，并把一部分“结构存在但行为不对”的实现重新拉回 Claude Code 2.1.88 的源码语义。

本轮可以确认有四类实质进展：

  1. Compact-5 Source-Aligned 主路径修正
  • 生产默认模式不再因为早层节省 token 而跳过后续 shaping；
  • Microcompact 改为每轮进入，再由内部 gate 决定 no-op；
  • 旧 early-exit 被隔离到显式 PRODUCT_EXTENSION 路径。
  1. Context-9 / Path-scoped Rules 从 Permission 误分类改回 Context
  • Project 路径规则开始进入真实 Read → lazy discovery → meta user context injection 主链；
  • 增加会话级去重、并发锁和 symlink escape 防护。
  1. Machine Evidence 从“完成率优先”转成“事实优先”
  • 原先不具备完整证据的 VERIFIED 被主动降级；
  • 新增 evidence consistency checker；
  • Reference-7 / Reference-5 / CCR-14 成为唯一正式 completion taxonomy。
  1. 测试治理更加可信
  • 本轮项目记录全量本地 Python 测试为 10151 passed, 10 skipped, 3 warnings, 345 subtests passed；
  • 文档明确不把本地测试写成 current-HEAD CI green。

但是，本轮还不能写成“B4 遗留问题已完成修复”。当前状态更准确的是：

B4 遗留问题修复：第一阶段有效完成
A0 Truth Reconciliation：部分完成
A1 Compact-5：部分完成
A2 Context-9：部分完成
A3 Durable Resume：未完成
A4 Cross-platform Isolation：未完成
Scheduler / Full Surface / Final CI：未完成

1. 本轮值得确认通过的修复

1.1 Compact-5：Source-Aligned 模式不再跨层 early-return

B4 原问题

原实现允许：

Layer 1 / Layer 2 / Layer 3
→ tokens_saved >= early_exit_tokens
→ return
→ 后续 shaper 不再执行

这会改变 Claude Code query.ts 中 pre-model context shaping 的整体调用结构。

当前修复

当前默认：

source_aligned: bool = True

在 Source-Aligned 路径中：

Result Budget
→ Snip
→ Microcompact
→ Context Collapse
→ AutoCompact

全部继续访问，由各层自身判断是否 no-op。

旧 early-exit 仅在：

source_aligned=False

时保留。

反馈结论

修复接受。

这是正确的设计边界：

Reference parity path
!=
Product optimization path

建议后续继续保持：

  • source_aligned=True 必须是生产 parity 默认；
  • source_aligned=False 不得参与 parity score；
  • 所有 PRODUCT_EXTENSION 都必须进入 divergence registry。

1.2 Microcompact：调用位置修正

B4 原问题

之前由 pipeline 外层直接判断：

mc_enabled == false
→ 整个 Microcompact stage 不进入

这和 Reference “调用 stage，再由内部 feature/config 决定 no-op”不同。

当前修复

现在每轮进入：

microcompact_typed_messages()

默认关闭时通过：

TimeBasedMCConfig(enabled=False)
force=False

在 Microcompact 内部返回 no-op。

反馈结论

修复接受。

这比“外层删掉整个阶段”更接近 Source control-flow。

1.3 Path-scoped Rules：语义归位正确

B4 原问题

之前 machine matrix 把：

path_rules

归入：

src/permissions
permission_context

这是语义错误。

当前修复

已经改为：

Read(file)
→ canonical path
→ discover matching project rules
→ claim once
→ inject meta user context

并且：

  • 不参与 Read 权限判定；
  • 规则只作为 context instruction；
  • 同一会话只注入一次；
  • concurrent Read 通过锁防重复；
  • rule symlink 越出项目 root 时拒绝注入。

反馈结论

方向正确，Project/CWD-level 子集修复接受。

这项修复应保留，不建议再回退到 Permission 层。

反馈结论

修复方向完全正确。

主动把错误 VERIFIED 降级是项目质量提升，不是完成度倒退。

2. 当前仍未完成的问题

2.1 Snip：仍然是 Open Gap

当前 Python：

def snip_compact(...):
    return list(messages), 0

因此当前 Layer 2 仍是固定 no-op。

这里需要区分两个问题：

问题 A：行为仍未实现

当前不能把 CCR-03 / R5-02 写成 complete。

问题 B：当前注释结论过强

当前文件注释写：

The TS implementation is a stub that returns null

但 recovered source 目前能确认的是：

query.ts
→ HISTORY_SNIP gate
→ snipCompactIfNeeded(...)
→ tokensFreed / boundaryMessage

而不是“Reference Snip 确认就是 stub”。

反馈建议

立即调整描述为：

Reference call-site confirmed;
Reference implementation body not yet fully recovered;
Python currently keeps an explicit no-op placeholder;
status = UNKNOWN/PARTIAL.

禁止继续用“TS 本身也是 stub”作为完成依据。

状态

OPEN / P0-P1。

3.2 Nested-directory rules 尚未完成

Reference 支持：

CWD
→ target file path
→ CWD 与 target 之间的 nested directories
→ nested CLAUDE.md / .claude/rules

当前 Python 的 root traversal 主要是：

cwd
→ parent
→ parent

并不会沿：

cwd
→ target.parent

下钻发现 nested rules。

示例

repo/
  src/
    service/
      .clawcodex/rules/service.md
      worker.py

当 CWD 是 repo/，读取 src/service/worker.py 时，Reference 可发现 src/service/.claude/rules；当前实现并不能完整覆盖该行为。

建议

实现：

cwd → target.parent

之间的目录链：

relative = target.parent.relative_to(cwd)
for segment in cumulative_segments(relative):
    process nested project memory/rules

并继续保持：

  • symlink canonicalization；
  • target escape rejection；
  • rule root provenance；
  • dedup；
  • conditional/unconditional 分离。

状态

OPEN / 重要。

4. Machine Evidence：已进步，但 baseline 模型本身仍有设计问题

4.2 更根本的问题：不能让一个 commit 内的文件写“自己的 SHA”

如果流程是：

把 HEAD 写入 yaml
→ 修改 yaml
→ commit
→ HEAD 改变

那么 YAML 天然立刻 stale。

这是自引用问题。

推荐修复模型

采用：

subject_commit
evidence_commit

例如：

subject_commit: <实际被验收的生产代码提交 X>
reference_commit: <Claude Code reference>
evidence_generated_from: <test run / extractor>

然后证据提交 Y 只允许修改：

docs/parity/**
scorecards/**
generated evidence

并要求：

git diff X..Y

不能出现 production code 修改。

更推荐

CI 中生成：

scorecard artifact

由：

GITHUB_SHA

动态绑定，不要求把同一个 HEAD SHA 回写入源码仓库。

状态

OPEN / A0 P0。

这次针对 B4 遗留问题的修复，最值得确认的是项目开始从“完成声明驱动”转为“事实证据驱动”。

唯一 taxonomy

Snip
