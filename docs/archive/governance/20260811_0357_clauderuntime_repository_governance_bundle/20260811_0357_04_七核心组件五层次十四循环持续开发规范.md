# ClaudeRuntime：7 核心组件 × 5 层次 × 14 循环机制持续开发规范

## 1. 最高优先级

后续 ClaudeRuntime 的 Source Parity 开发，最高优先级固定为：

```text
7 Core Components
×
5 Parity Layers
×
14 Auxiliary Loops
```

任何新功能、重构、性能优化，若与上述主线冲突，应优先保证核心 Parity。

---

## 2. 七个核心功能组件（Reference-7）

正式口径固定为：

1. **User**
2. **Interfaces**
3. **Agent Loop**
4. **Permission System**
5. **Tools**
6. **State & Persistence**
7. **Execution Environment**

### 重要约束

`Context / Memory` 不单独作为“第八组件”。

它分别归入：

- Agent Loop：context shaping / compaction / prompt construction；
- State & Persistence：durable memory / transcript / resume 等。

---

## 3. 五个 Parity 层次

建议统一定义为：

### L1 — Framework / Architecture Parity
系统级边界、职责划分、组件关系。

### L2 — Structure / Source Parity
package、module、symbol、关键 call-edge 的映射关系。

### L3 — Runtime Mechanism Parity
主运行路径、状态机、控制流、错误恢复、取消与终止。

### L4 — Auxiliary Mechanism Parity
围绕主 Agent Loop 的辅助循环和生命周期机制。

### L5 — Behavior / Safety / Continuous Parity
可观察行为、安全不变量、测试、版本跟踪与持续回归。

## 8. 开发优先级

- Main Query loop 终止/预算/错误恢复

- 关键 AUX 缺失

### P1
- 7/7 组件 Source Map
- 12+ Runtime Path 完整映射
- 14/14 AUX 完整映射
- State crash consistency
- Tool/Permission/Execution 契约统一

### P2
- Cross-surface contract
- Context semantic corpus
- Continuous Parity dashboard
- Reference version diff automation

### P3
- 非关键结构美化
- 纯命名一致性
- 不改变行为的文件形态模仿


## 10. 持续验收目标

最终目标不是“功能很多”，而是：

```text
7 / 7 核心组件可证明
5 / 5 层次有正式证据
14 / 14 循环机制有映射与测试
Critical Runtime Paths 无 UNKNOWN
Critical Safety Invariants 全绿
Intentional Divergences 全登记
```

只有达到上述条件，才能称为“高保真 Claude Code Runtime / Source Parity”。
