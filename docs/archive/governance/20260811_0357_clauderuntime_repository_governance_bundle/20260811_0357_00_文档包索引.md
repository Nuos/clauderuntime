# ClaudeRuntime 仓库清理、目录治理与 Parity 持续开发文档包

> 适用项目：`Nuos/clauderuntime`
> 文档目的：将仓库清理、目录迁移、文档治理、状态真值管理，以及 `7 核心组件 × 5 层次 × 14 循环机制` 的持续开发要求拆分为可独立执行、可长期维护的规范文件。

## 1. 文档包组成

| 编号 | 文件 | 用途 |
|---|---|---|
| 01 | `仓库非运行文件分类与清理规范` | 识别说明性、记录性、历史性、研究性文件，并定义保留/迁移/归档/删除规则 |
| 02 | `目录整理与迁移方案` | 定义目标目录结构、逐项迁移位置、命名与目录边界 |
| 03 | `文档信息架构与治理规范` | 规定 docs 目录如何分类，避免未来再次堆乱 |
| 04 | `7核心组件-5层次-14循环持续开发规范` | 把 Source Parity 主目标固化为长期开发主线 |
| 05 | `单一事实源与状态治理规范` | 解决 README / CHANGELOG / TODO / Progress / Parity Map 多头维护问题 |
| 06 | `清理迁移执行清单与验收门` | 将本次整理工作变成可执行 TODO、验证项和回滚门 |

## 2. 总原则

1. **生产运行代码与研究/历史材料分离。**
2. **根目录仅保留仓库契约、构建/安装、一级产品模块。**
3. **任何阶段性诊断、计划、进度、研究资料不得继续堆放根目录。**
4. **不以“少文件”为目标，以“边界明确、事实源唯一、长期可维护”为目标。**
5. **第一轮只做零信息损失迁移；第二轮再删除确认过时、重复或纯个人工具状态文件。**
6. **任何目录迁移必须同时修复 Markdown 链接、代码路径、脚本路径、CI/打包引用。**
7. **后续开发最高优先级保持：7 核心组件、5 层次、14 循环机制。**

## 3. 推荐执行顺序

```text
仓库盘点
  ↓
文件分类
  ↓
建立目标目录
  ↓
零信息损失迁移
  ↓
链接与路径修复
  ↓
测试/安装/打包/Parity 验证
  ↓
建立 docs/README.md
  ↓
冻结单一事实源规则
  ↓
第二轮历史垃圾清理
  ↓
进入 7×5×14 持续 Parity 开发
```
