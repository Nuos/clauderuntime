# ClaudeRuntime 文档信息架构与治理规范

## 1. 目的

防止本次迁移完成后，`docs/` 在未来数周内再次出现“所有 Markdown 都堆一级目录”的问题。

---

## 2. 文档八类模型

### Architecture
**回答：系统现在是什么？**

禁止放计划、历史进度。

### Parity
**回答：相对 Claude Code Reference 还差什么？**

保存机器可读映射、诊断、Scorecard、Runtime Path、Aux Loop。

### Plans
**回答：准备怎么做？**

只保存未完成/正在执行的开发计划。

### Progress
**回答：已经做了什么？**

按日期留档，不作为当前状态真值。

### Status
**回答：现在完成到哪里？**

只允许少量持续更新文件，作为当前项目状态入口。

### Reference
**回答：依据什么研究？**

Claude Code wiki、paper notes、source analysis 等。

### Guides
**回答：用户/开发者如何使用？**

不能混入内部项目管理记录。

### History / Archive
**回答：过去发生过什么 / 哪些资料已失效？**

用于保留历史，而不是指导当前开发。

---

## 3. 必须建立 `docs/README.md`

示例结构：

```markdown
# Documentation Index

## Current Architecture
- architecture/overview.md

## Current Status
- status/current.md
- status/backlog.md

## Claude Code Parity
- parity/README.md

## Active Development Plans
- plans/active/

## Progress History
- progress/

## Claude Code Reference
- reference/claude-code/

## User & Developer Guides
- guides/

## Archived Documents
- archive/
```

任何新增文档都必须能从此索引或其子索引进入。

---

## 4. 文档状态元数据

所有内部工程文档建议在顶部统一增加：

```yaml
status: ACTIVE | CURRENT | COMPLETED | ARCHIVED
owner: <module/team>
created: YYYY-MM-DD
last_verified: YYYY-MM-DD
reference_target: claude-code-x.y.z
clauderuntime_commit: <sha>
supersedes: <path or none>
superseded_by: <path or none>
```

作用：

- 判断文档是否有效；
- 知道依据哪个 Claude Code 版本；
- 知道依据哪个 ClaudeRuntime commit；
- 避免旧文档被 Agent 当成当前事实。

---

## 5. 文档生命周期

```text
DRAFT
  ↓
ACTIVE
  ↓
CURRENT / COMPLETED
  ↓
ARCHIVED
```

禁止：

- ACTIVE 与 ARCHIVED 内容互相覆盖；
- 老文件原地长期修改成完全不同的目标；
- 不标识状态的长期 Roadmap。

---

## 6. 更新责任

### 修改源码时

若改变：

- 核心组件边界；
- Runtime Path；
- Auxiliary Loop；
- 权限模型；
- 状态恢复语义；
- Execution Boundary；
- 工具协议；

必须同步评估：

```text
docs/architecture/
docs/parity/
docs/status/
```

### 完成计划时

从：

```text
docs/plans/active/
```

迁移至：

```text
docs/plans/completed/
```

### 新诊断产生时

进入：

```text
docs/parity/diagnostics/
```

或：

```text
docs/progress/YYYY/
```

不得直接放 `docs/` 一级。

---

## 7. 过时检测

CI 或审计脚本可逐步增加：

- 检查根目录多余 `.md`；
- 检查 `docs/` 一级白名单；
- 检查失效相对链接；
- 检查 `status: CURRENT` 文件数量；
- 检查 `last_verified` 超期；
- 检查 Reference target 版本漂移；
- 检查 Parity Map 是否存在 UNKNOWN/MISSING 未登记。

---

## 8. 文档一级目录白名单

建议 `docs/` 一级只允许：

```text
README.md
architecture/
parity/
plans/
progress/
status/
reference/
guides/
i18n/
assets/
history/
archive/
```

其他新增一级项应在 PR Review 中被拒绝，除非先修改本规范。
