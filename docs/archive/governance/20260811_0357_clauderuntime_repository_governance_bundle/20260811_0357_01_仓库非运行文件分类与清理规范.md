# ClaudeRuntime 仓库非运行文件分类与清理规范

## 1. 目标

识别项目中**说明性、记录性、历史性、研究性、宣传性、样例性**等不属于生产运行核心路径的文件，并明确：

- 哪些必须留在根目录；
- 哪些应移动到 `docs/`；
- 哪些应归档；
- 哪些可在第二轮清理中删除；
- 哪些虽然不是 runtime，但仍属于开发基础设施，不能误删。

---

## 2. 根目录必须保留

以下内容即使不是“运行代码”，也属于标准仓库契约或构建基础设施，不应移动：

```text
README.md
LICENSE
CHANGELOG.md
CONTRIBUTING.md

pyproject.toml
MANIFEST.in
requirements.txt
requirements.dev.txt
uv.lock

install.sh
install.ps1

.gitignore
.gitattributes
.github/
```

### 原因

| 类型 | 文件 | 说明 |
|---|---|---|
| 仓库入口 | `README.md` | 产品定位、安装、快速使用 |
| 法务 | `LICENSE` | 开源许可证 |
| 发布历史 | `CHANGELOG.md` | 版本级正式变化记录 |
| 贡献规范 | `CONTRIBUTING.md` | 开发者协作入口 |
| 构建/依赖 | `pyproject.toml` 等 | Python 构建、依赖、打包基础 |
| 安装 | `install.sh` / `install.ps1` | 产品安装入口 |
| Git/GitHub | `.gitignore` / `.github/` | CI、PR、Issue、仓库行为 |

**禁止为了视觉整洁将这些文件统一塞入 `docs/`。**

---

## 3. 根目录优先清理对象

### 3.1 `FEATURE_LIST.md`

**分类：历史 Feature/Roadmap 文档。**

问题：

- 与当前源码状态明显可能发生漂移；
- 容易与当前 Parity Scorecard、Progress、Issues 冲突；
- 名称会误导维护者把它当“当前真值”。

建议：

```text
FEATURE_LIST.md
→ docs/archive/roadmaps/FEATURE_LIST-legacy.md
```

文件头必须增加：

```markdown
> ARCHIVED
> 本文档为历史开发阶段快照，不代表当前实现状态。
> 当前实现状态请参见 docs/status/ 与 docs/parity/。
```

第二轮清理时，如果 Git 历史已足够承担追溯，可删除。

---

### 3.2 `TODOS.md`

**分类：历史问题记录 / 旧 Backlog。**

问题：

- 容易与 `docs/progress/`、`docs/status/`、GitHub Issues、Parity Map 形成多头真值；
- 已完成事项仍可能长期残留；
- Agent 或贡献者会错误判断项目当前状态。

建议：

```text
TODOS.md
→ docs/archive/backlog/TODOS-legacy.md
```

后续统一：

- GitHub Issues：工作项真值；
- `docs/status/current.md`：当前状态摘要；
- `docs/status/backlog.md`：高层级剩余缺口索引。

**禁止再新增根目录 TODO 文件。**

---

### 3.3 `assets/`

**分类：README / Benchmark / 宣传类文档资产。**

建议：

```text
assets/
→ docs/assets/
```

推荐再分：

```text
docs/assets/
├── readme/
├── benchmarks/
├── architecture/
└── parity/
```

迁移后必须修复 README、NEWS、文档中的相对路径。

---

### 3.4 `docs/reference/claude-code/`

**分类：Claude Code 研究资料 / Source Parity Reference。**

这类资料对项目研究价值很高，但不属于产品 runtime。

建议：

```text
docs/reference/claude-code/
→ docs/reference/claude-code/
```

推荐：

```text
docs/reference/claude-code/
├── README.md
├── source-analysis/
└── raw/
```

#### 个人编辑器工作区状态

若只是个人 UI 状态，建议第二轮删除并加入 `.gitignore`：

```text
workspace.json
graph.json
appearance.json
```

若有真正需要团队共享的编辑器配置，再单独保留最小集合。

---

### 3.5 `examples/`

**分类：产品样例。**

不是 runtime，但有使用价值。

优先建议：

```text
examples/
→ examples/
```

如这些内容主要用于宣传展示而不是开发者 API/CLI 示例，可改为：

```text
docs/examples/
```

---

## 4. 不属于 runtime，但必须保留的开发基础设施

### `tests/`

必须保留一级目录。它是功能正确性与 Parity 证据。

### `eval/`

必须保留一级目录。它是：

- Benchmark；
- 行为对比；
- Parity 评测；
- Harbor 等评估适配；
- 长期回归证据。

**不能因为“运行时不需要”而归档。**

### `scripts/`

必须保留一级目录。尤其：

```text
scripts/audit/
```

属于 Source Map / Parity 审计基础设施。

### `ui-tui/`、`ui-desktop/`

属于产品 Interfaces 层，不得以“非 Python runtime”为理由搬入 docs。

---

## 5. 第二轮才允许删除的内容

只有在第一轮迁移、链接修复和测试全部完成后，才处理：

```text
旧 FEATURE_LIST
旧 TODOS
个人编辑器工作区状态
重复 News 记录
完全失效且已被 Git 历史覆盖的旧计划
无引用、无测试价值、无研究价值的重复说明文件
```

删除前必须满足：

- Git 历史可追溯；
- 当前 docs 索引不再引用；
- README/CHANGELOG 不依赖；
- 脚本/CI 不依赖；
- Parity 证据不依赖。

---

## 6. 清理分类标签

后续盘点时统一使用以下标签：

```text
KEEP_ROOT
KEEP_ENGINEERING
MOVE_DOCS
MOVE_REFERENCE
MOVE_EXAMPLES
ARCHIVE
DELETE_CANDIDATE
UNKNOWN
```

任何 `UNKNOWN` 项在删除前必须人工确认。
