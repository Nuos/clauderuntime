## 3. docs 目标目录职责

### `docs/architecture/`

只描述“系统现在是什么”。

建议：

```text
architecture/
├── overview.md
├── agent-server.md
├── workflow-engine.md
├── components/
│   ├── user.md
│   ├── interfaces.md
│   ├── agent-loop.md
│   ├── permission-system.md
│   ├── tools.md
│   ├── state-persistence.md
│   └── execution-environment.md
└── runtime/
```

### `docs/parity/`

只描述“与 Claude Code Reference 相比是什么状态”。

```text
parity/
├── README.md
├── source-map/
├── runtime/
├── components/
├── layers/
├── auxiliary-loops/
├── diagnostics/
└── scorecards/
```

### `docs/plans/`

只保存尚未完成或正在执行的开发方案。

```text
plans/
├── active/
├── workflow/
└── completed/
```

### `docs/progress/`

保存按时间形成的历史进度记录：

```text
progress/
└── 2026/
    ├── 2026-08-10-development-progress.md
    └── ...
```

### `docs/status/`

只保存**当前**状态：

```text
status/
├── current.md
└── backlog.md
```

### `docs/reference/`

研究与外部参考：

```text
reference/
└── claude-code/
```

### `docs/archive/`

失效但仍需保留的信息：

```text
archive/
├── roadmaps/
├── backlog/
├── diagnostics/
└── progress/
```

## 4. 命名规范

### 当前架构

```text
overview.md
agent-loop.md
permission-system.md
```

不使用日期。

### 计划

```text
<topic>-plan.md
```

### 进度

```text
YYYY-MM-DD-<topic>-progress.md
```

### 诊断

```text
YYYY-MM-DD-HHMM-<topic>-diagnostic.md
```

### 历史归档

```text
<original-name>-legacy.md
```

或：

```text
YYYY-MM-DD-<original-name>-archived.md
```

---

## 5. 禁止事项

以后禁止：

```text
/2026-xx-xx-diagnostic.md
/TODO-new.md
/feature-list-v2.md
/docs/2026-xx-xx-random-plan.md
/docs/new-architecture-v3.md
```

所有新文档必须先进入既定类别。

---

## 6. 迁移完成后的根目录目标

最终根目录应能一眼识别为：

```text
Repository Contract
+ Build / Install
+ Product Source
+ Test / Eval / Scripts
+ Interfaces
+ Examples
+ Documentation
```

而不是：

```text
源码 + TODO + 研究资料 + 图片 + 临时计划 + 历史进度 + Wiki 全混在一起
```
