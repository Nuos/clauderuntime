# 开发进度记录模板

> 阶段：`F?`  
> 日期：`YYYY-MM-DD`  
> Subject commit：`<sha>`

# 1. 本轮目标

说明本轮解决哪个功能问题，不要只写“对齐 Reference”。

# 2. 完成内容

- 功能 A；
- Bug B；
- 安全修复 C。

# 3. 针对性测试

```text
command / test group
XX passed
0 failed
```

# 4. 组合测试

若没有，写：`本轮无跨模块组合测试需求`。

# 5. Full Suite

只有阶段收尾才填写；否则写：`未执行，按开发阶段测试规则不要求每次小改全量测试。`

# 6. Reference 对照与差异

## DIFF-xxx

```text
REF Source:
REF Behavior:
Python File/Symbol:
Python Behavior:
Difference:
Reason:
User Impact:
Safety Impact:
Status:
Accepted:
```

# 7. 本轮新增/关闭差异

```text
新增：N
关闭：N
继续接受：N
```

# 8. 剩余功能缺口

只列真实功能缺口；纯 Source 细节放到“延期 Reference 细节”。

# 9. 延期 Reference 细节

明确哪些 Reference 行为暂不复刻，以及原因。

# 10. 当前阶段结论

允许：

```text
FUNCTIONAL_COMPLETE
FUNCTIONAL_ADAPTATION
LIMITED
```

禁止模糊写：

```text
100% 对齐
完全一致
```

除非确实在独立审计中证明。


# Reference 分级对齐记录

每个本轮关键功能必须填写：

```text
REFERENCE_CERTAINTY:
ALIGNMENT_POLICY:
Reference 是否可确定：是 / 部分 / 否
已确定部分是否完成对齐：是 / 否 / 不适用
未确定部分是否只做核心功能一致：是 / 否 / 不适用
差异是否已记录到代码附近：是 / 否
差异是否已记录到全局 registry：是 / 否
```
