# 源码差异标记与注释规范

# 1. 目标

让开发者在打开一个 Python 模块或关键函数时，不需要查几十份历史文档，就能立即知道：

```text
参考源码在哪里
参考功能是什么
Python 现在怎么做
为什么不完全一样
差异是否接受
```

---

# 核心修订：分级 Reference 对齐

> **凡是 Claude Code recovered source 能够确定的功能、模块、函数契约、关键控制行为，仍然以 Claude Code 2.1.88 为对齐目标；只有 Reference 具体实现无法确定或恢复不完整的部分，才降低为“核心功能一致 + Python-native 实现 + 差异透明记录”。**

B6 不是“所有模块都只要求功能类似”，而是：

```text
Reference 可确定
→ 必须优先对齐

Reference 部分可确定
→ 已确定部分必须对齐
→ 未确定部分允许功能类似

Reference 无法确定
→ 只要求核心功能/用户目标一致
→ 必须记录不确定性与 Python 实现

Product Extension
→ 明确与 Reference 分离
→ 不得伪装为 Claude Code 原有行为
```

| Reference 证据等级 | 定义 | 开发要求 |
|---|---|---|
| `R1_CONFIRMED` | 源文件、symbol、函数体/关键控制流能够确认 | **必须对齐功能、模块职责、关键行为和已知安全/状态语义** |
| `R2_PARTIALLY_CONFIRMED` | call-site、接口、返回契约或部分逻辑可确认，但实现体不完整 | **已确认部分必须对齐；未知部分允许 Functional Adaptation** |
| `R3_UNKNOWN` | recovered source 无法确认具体实现，只能确认功能名称/高层目的 | **只要求核心功能一致，并明确标记 UNKNOWN_REFERENCE** |
| `R4_PRODUCT_EXTENSION` | ClaudeRuntime 自己新增的功能或增强 | **独立记录，不计作 Claude Code 对齐能力** |

Known Differences:
    不完全复刻 Reference 的 content-replacement 和 worktree 自动恢复策略。

Functional Status:

# 3. 函数级模板

```python
# REF-DIFF:
# REF: services/compact/...::snipCompactIfNeeded
# REF-BEHAVIOR: call-site confirmed; implementation body not fully recovered.
# PY: src/services/compact/snip_compact.py::snip_compact
# PY-BEHAVIOR: currently conservative no-op.
# DIFF: Python does not perform historical snipping yet.
# WHY: RECOVERED_SOURCE_GAP.
# USER-IMPACT: LOW; other compact layers still control context growth.
# SAFETY-IMPACT: NONE.
# STATUS: UNKNOWN_REFERENCE / DEFERRED_REFERENCE_DETAIL.
```

---

# 4. 什么时候必须标

以下情况必须添加或更新：

- 从 Claude Code TS 转译新模块；
- 对应 Reference symbol 的关键函数；
- Python 改成不同算法；
- 使用不同 persistence；
- 使用不同 process/async 模型；
- 平台能力不同；
- Reference source 缺失；
- 为安全主动加强；
- 为性能加入优化；
- Product extension 改变行为。

---

# 5. 什么时候可以不标

纯内部 helper 且：

- 不对应 Reference 行为；
- 不改变用户功能；
- 不涉及安全/状态；
- 只是 Python 代码整理。

不需要每个小函数都塞入冗余注释。

---

# 6. 全局 registry 字段

每个重要差异使用统一结构：

```yaml
- id: DIFF-CCR03-001
  area: CCR-03
  feature: snip_compact
  reference:
    file: services/compact/...
    symbol: snipCompactIfNeeded
    behavior: call site known; body not fully recovered
    certainty: PARTIAL
  python:
    file: src/services/compact/snip_compact.py
    symbol: snip_compact
    behavior: conservative no-op
  difference: Python currently skips snip behavior
  reason: RECOVERED_SOURCE_GAP
  user_impact: LOW
  safety_impact: NONE
  compatibility_impact: MEDIUM
  status: DEFERRED_REFERENCE_DETAIL
  accepted: true
  tests:
    - tests/parity/test_compression_pipeline_parity.py
```

---

# 7. 规则

1. `Reference behavior` 只写源码能确认的事实；
2. 不确认就写 `UNKNOWN_REFERENCE`；
3. `Reason` 必须具体；
4. `accepted=true` 不等于“Reference 一致”；
5. 安全差异不能因为 accepted 就隐藏；
6. 用户可见行为有变化时必须更新 progress；
7. 代码注释和 registry 冲突时，必须修正文档，不允许长期双状态。


# 对齐优先级硬规则

## R1_CONFIRMED
Reference 能确认时，不得只满足“功能大致一样”。模块职责、输入输出契约、关键控制顺序、feature gate、状态转换、失败行为、安全边界和用户可见效果应优先对齐。

## R2_PARTIALLY_CONFIRMED
已确认的 call-site、gate、contract 和返回语义必须对齐；未知算法不允许猜成“Reference 事实”。

## R3_UNKNOWN
只要求核心功能目标一致，并明确标记：

```text
REFERENCE_CERTAINTY = R3_UNKNOWN
ALIGNMENT_POLICY = FUNCTIONAL_CORE_ONLY
```
