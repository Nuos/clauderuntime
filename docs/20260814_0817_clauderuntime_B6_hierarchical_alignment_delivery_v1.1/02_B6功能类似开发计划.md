# B6 功能类似开发计划

> 文档编号：`CR-B6-FUNCTIONAL-SIMILARITY-PLAN`  
> 起始 HEAD：`dc7393bb05de7dc328d5206e19ba2e15997c1656`  
> 目标：**Reference 可确定部分继续对齐；Reference 不确定部分优先完成核心功能，并以差异记录代替无根据的 1:1 猜测。**

---

# 核心修订：分级 Reference 对齐

> **凡是 Claude Code recovered source 能够确定的功能、模块、函数契约、关键控制行为，仍然以 Claude Code 2.1.88 为对齐目标；只有 Reference 具体实现无法确定或恢复不完整的部分，才降低为“核心功能一致 + Python-native 实现 + 差异透明记录”。**

B6 不是“所有模块都只要求功能类似”，而是：

```text
Reference 可确定
→ 必须优先对齐

Reference 部分可确定
→ 已确定部分必须对齐
→ 未确定部分允许功能类似

Reference 无法确定
→ 只要求核心功能/用户目标一致
→ 必须记录不确定性与 Python 实现

Product Extension
→ 明确与 Reference 分离
→ 不得伪装为 Claude Code 原有行为
```

| Reference 证据等级 | 定义 | 开发要求 |
|---|---|---|
| `R1_CONFIRMED` | 源文件、symbol、函数体/关键控制流能够确认 | **必须对齐功能、模块职责、关键行为和已知安全/状态语义** |
| `R2_PARTIALLY_CONFIRMED` | call-site、接口、返回契约或部分逻辑可确认，但实现体不完整 | **已确认部分必须对齐；未知部分允许 Functional Adaptation** |
| `R3_UNKNOWN` | recovered source 无法确认具体实现，只能确认功能名称/高层目的 | **只要求核心功能一致，并明确标记 UNKNOWN_REFERENCE** |
| `R4_PRODUCT_EXTENSION` | ClaudeRuntime 自己新增的功能或增强 | **独立记录，不计作 Claude Code 对齐能力** |

---

# 0. 开发总原则

B6 不再以“7/7 + 5/5 + 14/14 全部 Source-Aligned VERIFIED”为结束条件。

新的排序：

```text
核心功能缺失
> 用户可见 Bug
> 安全旁路
> 状态/恢复 Bug
> 跨平台可用性
> 重要功能限制
> Reference 细节差异
> 纯证据完善
```

任何 Reference 细节如果不影响核心功能，可以直接标：

```text
DEFERRED_REFERENCE_DETAIL
```

---

# 1. Wave F0 — 先建立“差异透明”开发制度

## 目标

以后每一处转译/改写都能够回答：

```text
Claude Code 源码是什么？
Python 现在是什么？
哪里不一样？
为什么不一样？
这个差异是否影响用户？
是否影响安全？
是否接受？
```

## 必做

1. 在新建/重大修改模块的模块 docstring 增加 `Reference Mapping`；
2. 在关键函数附近增加简短 `REF-DIFF` 块；
3. 在 `docs/reference-differences/registry.yaml` 建全局台账；
4. 每个开发进度文件必须有“Reference 差异”小节；
5. PR/commit review 必须检查：功能、测试、差异记录三者同时更新。

## Exit

差异记录制度落地即可，不要求每个历史文件一次性补全。

# 2. Wave F1 — Core Loop / Tools / Permission 快速功能收口

这些模块当前成熟度最高，应优先正式标 `FUNCTIONAL_COMPLETE` 或 `FUNCTIONAL_ADAPTATION`，不要继续为细小 call-edge 阻塞。

## Agent Loop

确保：

```text
Prompt
→ Context
→ Model
→ Tool Use
→ Permission
→ Tool Execution
→ Result
→ Continue/Stop
```

功能稳定。

不要求与 `query.ts` 每一个内部 helper 调用一致。

## Permission

必须保留：

- deny / allow / ask；
- interactive approval；
- headless fail-safe；
- tool-specific check；
- Permission 与 Sandbox 分开。

Reference 的 classifier/模式细节若 Python 不完全一致，记录为 `FUNCTIONAL_ADAPTATION`。

## Tools

目标：

- Read / Write / Edit / Bash / Glob / Grep；
- tool registry；
- permission gate；
- result mapping；
- concurrency-safe tools；
- abort/timeout；
- background Bash。

只要用户功能完整，内部 orchestration 不需要逐 symbol 复刻。

---

# 3. Wave F2 — Context / Compact：从“完全相同”改为“功能覆盖”

## Context

要求保留主要能力：

- system prompt；
- environment context；
- project instructions；
- Managed/User/Project/Nested path-scoped rules；
- auto memory；
- tool metadata；
- conversation；
- tool result；
- compact summary。

当前 path-scoped rules 已经具有 Managed/User/Project/Nested 和 next-model-call exactly-once 机制，可以按功能目标继续收口。

## Compact

B6 不再要求五层算法完全等价。

目标变成：

```text
长对话不会无限增长
旧工具结果能够被预算/裁剪
必要上下文尽量保留
接近窗口限制时能够摘要
压缩后规则/文件上下文可以重新加载
```

### Snip 处理策略

Reference body 未完整恢复，因此有两种允许方案：

**方案 A（最快）：** 保持当前 no-op，标记 `UNKNOWN_REFERENCE + DEFERRED_REFERENCE_DETAIL`，依靠 Tool Result Budget / Microcompact / AutoCompact 完成长对话管理。

**方案 B（推荐后续）：** 实现一个 Python-native 安全 Snip，只裁剪可重建的旧工具结果，标记 `FUNCTIONAL_ADAPTATION`。

不得再宣称“Reference 本身就是 stub”。

---

# 4. Wave F3 — State / Resume：满足常见恢复即可

严格 Source-Aligned 阶段要求：content replacement、worktree 自动恢复、真实进程替换、所有 Reference 恢复细节。

B6 降低为：

```text
同进程 resume 可用
服务重启后能从 transcript + 安全 metadata 重建常见后台 Agent
不持久化 API key / provider object / temp permission
缺失 worktree 时明确失败
并发 resume 单 winner
失败不能伪装 running
```

当前这些主体已经存在。

因此下一阶段：

1. 补一个真正的新进程 smoke test；
2. 将 content replacement / deleted worktree auto-recovery 标记为 `DEFERRED_REFERENCE_DETAIL`；
3. 如果缺失 worktree，明确错误即可，不强制复刻 Reference 自动恢复策略；
4. Resume 模块可在 smoke test 通过后标 `FUNCTIONAL_ADAPTATION`。

---

# 5. Wave F4 — Scheduler：接受 Python-native 持久化方案

不再要求完整复刻 Reference：

```text
file-backed scheduled_tasks.json
filesystem watcher
cross-process owner takeover
```

B6 核心目标：

- create/list/delete；
- recurring；
- one-shot；
- durable one-shot；
- restart restore；
- no catch-up；
- expiry；
- last_fired_at；
- wakeup；
- permission/isolation 仍生效。

当前 `SessionCronScheduler + snapshot/restore` 可以作为 `FUNCTIONAL_ADAPTATION`。

Reference 的 file watcher / owner takeover 记录为：

```text
DEFERRED_REFERENCE_DETAIL
Reason: Python runtime simplification / product scope
```

# 6. Wave F5 — Isolation：功能底线保留，但不追求同底层实现

这是降低要求后仍不能完全跳过的模块，因为它涉及真实副作用。

## macOS

保留现有 Seatbelt 实现。

## Linux

优先实现一种可用的 backend：

```text
bubblewrap OR Landlock
```

不要求同时实现所有 Reference network/filesystem 配置细节。

## Windows

优先保证：

- Job Object / process tree；
- workspace path boundary；
- secret scrub；
- 明确 capability 信息。

如果暂时无法提供完整 OS sandbox：

```text
status = LIMITED
```

且当调用方明确 `require_isolation=True` 时必须 fail-closed。

功能类似阶段不允许把不存在的 isolation 写成“已沙箱”。

# 7. Wave F6 — MCP / Hooks / Subagent / Background Lifecycle

这里优先用户功能，不追逐全部内部状态。

## MCP

完成：

```text
connect
→ discover tools
→ expose capabilities
→ permission
→ invoke
→ disconnect / failure cleanup
```

不要求 transport/OAuth 细节全部与 Reference 相同。

## Hooks

完成主要事件：

- PreToolUse；
- PostToolUse；
- Stop；
- Session/Agent 关键 lifecycle；
- timeout/process cleanup。

27 个事件逐项严格 parity 可以延期。

## Subagent

完成：

- spawn；
- isolated messages/context；
- tool scope；
- background；
- result/summary；
- SendMessage；
- stop/resume。

Reference 的内部 sidechain 细节只需记录。

---

# 8. Wave F7 — Surface：Smoke Compatibility 替代 Full Differential

不再要求：

```text
CLI/TUI/Desktop/IDE 同一 trace 每个字段完全一致
```

新要求：每个正式支持 Surface 至少做：

1. 启动；
2. 普通回答；
3. 一个 Read；
4. 一个需要 Permission 的动作；
5. interrupt；
6. session continue/resume（若 Surface 支持）。

只要都进入 shared core 并完成主要功能，即可标：

```text
FUNCTIONAL_ADAPTATION
```

---

# 9. Wave F8 — 测试与发布收口

开发阶段继续执行“针对性测试优先”：

```text
单模块改动 → targeted tests
多模块改动 → affected combination tests
阶段结束 / 发布 / 合并 → full suite
```

最终建议仍建立 GitHub CI，但不再把“没有 CI”视为功能开发阻塞项。

CI 作为：

```text
RELEASE_GATE
```

而不是：

```text
FEATURE_IMPLEMENTATION_GATE
```

# 10. B6 完成条件

B6 可以宣布“核心功能开发完成”时：

```text
Reference-7：7 个组件均至少 FUNCTIONAL_COMPLETE / FUNCTIONAL_ADAPTATION
Reference-5：5 层均有可工作的 Python owner
CCR-14：14 项均有 FUNCTIONAL_* / LIMITED / 明确 DEFERRED_REFERENCE_DETAIL
核心安全旁路 = 0
核心 MISSING = 0
每个关键差异已记录
关键 targeted tests 通过
full local suite 阶段收尾通过
```

不再要求：

```text
0 PARTIAL in source parity maps
0 reference-symbol gaps
0 callgraph differences
0 source-level divergences
```
